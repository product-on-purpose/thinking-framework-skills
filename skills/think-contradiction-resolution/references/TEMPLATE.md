## The contradiction

- **Opposing pair (A vs B):** to get more of **[A]** we must accept less of **[B]**. [state the tension as an explicit pair]
- **Type:** [**technical** - improving parameter A degrades a *different* parameter B] OR [**physical** - one *single* parameter must hold two opposite values at once: name the parameter and the two values]
- **Why it has felt inevitable:** [the assumption or apparatus that makes the trade-off look unavoidable]

## Ideal Final Result (IFR)

[The end-state, implementation-free: the required benefit delivered with no new cost, no new harm, ideally no new mechanism. No "how." Not a reworded goal - strip the apparatus so it is clear how much is actually necessary.]

## Dissolution attempts

For a **physical** contradiction, work the four separation principles. For a **technical** contradiction, prompt with inventive principles (treat any matrix as a heuristic, not a lookup). Record every attempt, not just the winner.

| Operator | Attempt (how the requirements might be separated / inverted) | Result |
|---|---|---|
| Separate in **time** | [each requirement holds at a different moment?] | [dissolves / partial / no] |
| Separate in **space** | [each holds in a different place or part?] | [dissolves / partial / no] |
| Separate by **scale / system level** | [move a requirement to a super- or sub-system?] | [dissolves / partial / no] |
| Separate by **condition** | [each holds under a different case, segment, or trigger?] | [dissolves / partial / no] |
| Inventive principle ([name], technical only) | [e.g. segmentation, asymmetry, nesting, the other way round] | [dissolves / partial / no] |
