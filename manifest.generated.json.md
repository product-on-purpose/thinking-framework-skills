# manifest.generated.json

The resolved, fully-expanded plugin manifest: `library.json` plus what is actually on disk for each skill, flattened into one JSON file.

## What is in it

Top-level metadata for the plugin (`name`, `version`, `tier`, `standard`) followed by a `skills` array with one entry per shipped skill. Each skill entry carries its `name` (the installed `think-` prefixed id, e.g. `think-premortem`), its `path` to the `SKILL.md` on disk (e.g. `skills/think-premortem/SKILL.md`), and the full `description` resolved from that skill's frontmatter. A `commands` array is also present (currently empty). At the time of writing it lists all 31 skills.

## Why it matters

It is the single denormalized view a tool can read to know the plugin's identity and its complete skill roster without crawling the `skills/` tree and parsing each `SKILL.md` frontmatter. Loaders, the catalog, and the docs generator can resolve "what ships, under what name, from what path, with what description" in one read. Without it, every consumer has to re-discover and re-parse the on-disk skills itself.

## What produces it, what consumes it

Generated by the agent-skills-toolkit `gen-manifest` step from `library.json` and the on-disk skills. It is consumed by tooling that needs the resolved roster: packaging, validation, and downstream generators. It is a sibling input to the docs site, which is itself a generated view (see `scripts/gen-site.mjs`).

Note: this manifest currently omits a `license` field. The root `LICENSE` file (Apache-2.0) is authoritative for licensing.

## Do not hand-edit

This file is generated. Edit `library.json` and the individual `skills/*/SKILL.md` files instead, then regenerate the manifest with the agent-skills-toolkit `gen-manifest` generator. Hand edits here will be overwritten on the next regeneration and will drift from the source of truth. See the authoring guide at [docs/internal/AUTHORING.md](./docs/internal/AUTHORING.md) and the skills themselves under [skills/](./skills/).
