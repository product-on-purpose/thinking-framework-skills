---
title: How to read a page
description: Every framework page is layered so you can stop at any depth, from a 20-second card to the full evidence dossier.
---

Every framework page uses the same four layers. Read as deep as you need and stop.

1. **Quick facts (20 seconds).** A card at the top: the mechanism in one line, the artifact it produces, its evidence tier, its domain, and when to use it (and when not to). Enough to decide whether this is your tool.
2. **The core (2 minutes).** The mechanism explained, the numbered procedure, the output format, and an explicit "when NOT to use this." This is everything you need to run it.
3. **Deep dive (collapsible).** A fully worked example on a shared scenario (a B2B SaaS weighing a free-tier launch), so you see the artifact at quality.
4. **Grounding (collapsible).** The full evidence dossier: what the research does and does not show, the transferred-evidence flag, the honest caveats, and the graded source list. For the skeptic who wants to check the claim.

Beginners stop after layer 2. Skeptics and advanced readers open the collapsible deep-dive and grounding sections.

## Three honesty cues to notice

- **The tier badge** (S/M/P/V/A/C/X) tells you how strong the evidence is. See [the evidence model](./evidence-model/).
- **"When NOT to use this"** is on every page on purpose. A framework applied to the wrong situation is worse than none.
- **The dossier's "what this does NOT show"** keeps the page from overselling. If a page makes a quantified claim, the source for it is in the grounding.

## Pages are generated from the skills

Each framework page is a generated view of the skill's own files (`SKILL.md`, the dossier, the worked example). The skill is the source of truth; the page renders it, so the two can never drift.
