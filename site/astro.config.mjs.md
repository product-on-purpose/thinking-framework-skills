# astro.config.mjs

The Astro build configuration for the docs site. Hand-authored.

## What it is

A standard `defineConfig` export that wires up Astro + Starlight + astro-mermaid for the generated documentation site, deployed to GitHub Pages.

## What it does

- Sets `site` to `https://product-on-purpose.github.io` and `base` to `/thinking-framework-skills`, the project subpath GitHub Pages serves from.
- Registers integrations in order: `astro-mermaid` first, then `starlight`. The order is required - mermaid must load before Starlight.
- Configures the mermaid theme (`default` with `autoTheme`) and a few theme variables: a blue `lineColor` (`#5C7CFA`) and a system-ui font stack. Diagrams render client-side, and the bundle only loads on pages that contain one.
- Defines the Starlight title, description, GitHub `editLink`, and custom CSS.
- Injects GA4 head tags only when `PUBLIC_GA_ID` is set in the environment. With no ID (local and CI builds), `gaHead` is empty and nothing is tracked.
- Overrides the Footer component with `./src/components/SiteFooter.astro` to show the library version label. (The full `starlight-versions` archive plugin is deferred until there is a real prior version.)
- Lays out the sidebar: a hand-listed "Start here" group, then autogenerated groups for `learn`, `explore`, `frameworks`, `families` (labeled Domains), `recipes`, `evidence`, and `about`.

## Why it matters

Without this file the site has no base path (links break on GitHub Pages), no mermaid rendering, no sidebar structure, and no opt-in analytics. It is the seam between the generated content and a working published site.

## Produced and consumed by

Hand-authored and committed. The `astro` and `astro build` CLIs read it; `npm run gen` (scripts/gen-site.mjs) produces the page content under `src/content/docs/` that the sidebar's autogenerate entries pick up. This config is not generated - edit it directly. The pages it organizes are generated, so edit a skill and regenerate rather than editing those.
