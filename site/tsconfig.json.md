# tsconfig.json

The TypeScript configuration for the Astro docs site, hand-authored.

## What it does

It is a three-property config that extends Astro's bundled `astro/tsconfigs/strict` preset, then sets the project boundaries:

- `extends`: pulls in Astro's strict compiler options (strict null checks, no implicit `any`, the JSX settings Astro needs) so this file only has to declare what differs.
- `include`: `.astro/types.d.ts` (the generated Astro type definitions) plus `**/*`, so every file in `site/` is type-checked.
- `exclude`: `dist`, the build output, which should never be type-checked.

## Why it matters

Without it, editor tooling and `astro build` have no project root or compiler options to work from, so the `.astro` components and `astro.config.mjs` are checked with loose defaults or not at all. Extending the strict preset is what surfaces type errors during editing and the build. A dedicated `astro check` pass is available but is not wired into the npm scripts or CI; the deploy workflow runs `npm run build`.

## Produced and consumed by

Hand-authored. It is part of the site scaffold, not generated by `scripts/gen-site.mjs` (that script emits the generated pages under `src/content/docs/{frameworks,families,recipes,evidence}` plus the `explore/` lens and map pages, which are gitignored, alongside `src/generated/`; the hand-authored pages such as `start/`, `learn/`, `about/`, and `explore/chooser.mdx` are committed). It is consumed by the TypeScript compiler, `astro check` if run, and editors providing IntelliSense over the site source.

To change type-checking behavior, edit this file directly. It is small and stable, so changes are rare.
