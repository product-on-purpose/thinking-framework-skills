# Recipes

Recipes are composable workflows: short, ordered chains of skills that solve a recurring job end to end. Each recipe names the skills to run, in order, what to carry forward (compressed) between steps, and the composite artifact produced.

Each recipe ships on three surfaces, all generated from one source so the chain exists once:

- a **workflow component** in [`_workflows/`](../_workflows/) (a `steps:` list of skills, validated by the Standard's S5 check) - the source of truth, which these docs describe in prose;
- a **slash command** per recipe, `/think-<recipe>` in [`commands/`](../commands/), which runs the chain inline so you can see and steer each step;
- for two recipes, a **reasoning subagent** in [`agents/`](../agents/) (Claude Code only) that runs the whole chain in its own context and hands back only the composite artifact: `think-stress-test-decision` and `think-audit-reasoning`. Why those two and not the rest: [`docs/internal/AUTHORING.md`](../docs/internal/AUTHORING.md#reasoning-subagents-when-a-recipe-becomes-one).

Commands and subagents are generated by `npm run gen:recipe-commands`; never hand-edit them.

**Token discipline:** between steps, carry forward only the compressed artifact (the chosen frame, the shortlist, the ledger), not the full working text of the prior step. The audit flagged unbounded recipe context as the main operational risk; compress at each handoff.
