## [Unreleased]

### Added
- **The gate's warning BREAKDOWN is asserted too, not just the total.** `docs/internal/gate-composition.json` holds the per-requirement tally and the Standard-0.13 counterfactual; `check.mjs` now tallies the run's `[warn] <REQ>:` lines and fails if they disagree with it, and `check-counts.mjs` asserts the ten further published sentences that quote the subtotal or the counterfactual. 13 new tests (286 -> 299).
  - **Prompted by the same class of break, one level down.** PR #122 asserted the headline total and stopped there. The `G9` sweep below took the run 129 -> 90, and the three figures published *beside* the total - the post-0.8 subtotal (122), the per-requirement breakdown (`39 G9` among them), and the 0.13 counterfactual (123 errors) - were live in **six** sentences across `README.md`, `docs/conformance.md`, `docs/internal/backlog.md` and `docs/internal/release-process.md`, and asserted in **none**. The sweep would have merged leaving six freshly false claims behind a green gate.
  - **The breakdown is checked in both directions**, because the direction that mattered here is the counter-intuitive one. A new requirement family appearing is obvious drift. A family *disappearing* - which is exactly what `G9` did - would pass a one-way check while every page went on naming 39 source-docblock warnings that no longer existed.
  - **The subtotal is derived, never stored.** It is the sum of the `G`-prefixed families in the breakdown, so the two cannot disagree. `U5` (the seven caveat-first description scores) is deliberately excluded: it is not post-0.8 documentation debt, and folding it in would overstate the debt on every page quoting the figure.
  - **One figure is honestly weaker, and the file says so in those words.** The 0.13 counterfactual cannot be asserted against a normal run - producing it means temporarily declaring `0.13` in `library.json`, which CI must not do - so it is hand-measured at each cut and the gate proves only that the prose matches the recorded measurement. It was **re-measured, not arithmetic'd**: `convergent, 84 errors, 7 warnings` at toolkit `93da438`.
- **The gate's own warning count is now asserted instead of hand-copied.** `docs/internal/gate-warning-count.txt` holds the canonical number; `check.mjs` fails if a live evaluator run disagrees with it, and `check-counts.mjs` fails if any published sentence does. New pure lib `scripts/lib/warning-count-lib.mjs` + 8 tests (278 -> 286).
  - **Prompted by breaking it.** The skill-selection eval (#120) added four source files with no `what-it-is` / `what-it-does` / `why` / `used-by` header docblock (ADR 0024 D1.2), taking the run **129 -> 133** and making the figure published in `README.md` and `docs/conformance.md` wrong the moment it merged. Fixed at the cause - the four docblocks - rather than by editing the number, which returns the run to `0 errors, 129 warnings` with its documented composition intact (71 `G8`, 39 `G9`, 7 `G7`, 5 `G10`, 7 `U5`).
  - **This is the fourth time the count went stale**, so the fix is structural rather than another correction. Historical provenance sentences are excluded by construction, with a test that reds if a pattern ever widens to match them.
- **The output half for the meta-skills, and scoped stamping to go with it.** `finalize.mjs` gains `--stamp a,b,c` / `--no-stamp` (the safer `--no-stamp` wins if both are passed) and `--provenance <file>`; `scoreOutput` takes the same optional provenance bag `scoreTrigger` already had. 7 new tests (271 -> 278).
  - **Why the flag was needed at all:** `finalize.mjs` stamped every shipped framework unconditionally, so finalizing a 3-skill meta run would have re-dated **63 sidecars it never measured** - the same bug-class the trigger path closed earlier in this release, on the other path.
- **A second behavioral eval, because the first one could not see the front door.** `skill-selection` routes each situation against the **installed roster** - the 67 skills plus 10 commands in `manifest.generated.json`, reduced to the `name` + `description` pairs an agent actually sees - instead of the advisor's `recommendable.json`. New: `scripts/lib/selection-lib.mjs` (pure), `scripts/eval/extract-roster.mjs`, `scripts/eval/skill-selection.workflow.mjs`, `scripts/eval/score-selection.mjs`, and a `--roster` mode on `extract-cases.mjs`. 36 new tests (235 -> 271).
  - **Why a second instrument rather than a second run.** The trigger eval routes against the 63 shipped frameworks. The four meta-skills are deliberately absent from that corpus - it is the advisor's list of things to *recommend*, not a roster of installed skills - so a blind router reading it can never return `framework-advisor` as a pick. They were not failing that eval; they were invisible to it. **Framework routing and skill selection are different questions.**
  - **Commands are kind-qualified** (`command:<slug>`), so a command pick is a distinct string from a skill pick and the existing strict-equality scorer surfaces command interference with no change. The one real collision - `think-research-framework` ships as both a skill and a command - is normalized, because there the two ids are the same capability.
  - **The router persona is an agent choosing a tool**, not "the routing core of an advisor". An advisor persona structurally never selects itself, which would have baked in the exact blindness being removed.
  - **New case type `[gate]`.** A "Should NOT trigger" bullet whose own prose says the authoring skill IS the right tool and only its *behavior* differs (the advisor's insufficient-signal case, where the correct move is exactly one clarifying question) is an output-level contract a routing eval cannot judge. It is emitted as `type: "gate"`, excluded from every figure, and reported - never scored as an anti-case, where a correct pick would have been recorded as a **false fire**.

### Security
- **`site/` dependency advisories: 10 back down to 6, but the critical is still there.** The v0.14.0 cut re-measured `npm audit` in `site/` and found it had regressed to 10 findings (2 low, 3 moderate, 4 high, 1 critical) against an unchanged `package-lock.json` - new advisories landing on the same pinned versions rather than anything this repo did. A non-breaking `npm audit fix` takes it to **6 (1 low, 3 moderate, 1 high, 1 critical)**. `site/package.json` is untouched, so no declared dependency moved; the change is 32 lines of `package-lock.json` resolving transitive versions. The site still builds (269 pages), and the rendered-link and route-parity guards pass.
  - **What is left, and why `--force` was not used.** All six now require a major bump, so `npm audit fix --force` would take them by upgrading the framework underneath a generated product surface: `astro@7.3.2` (the **critical** XSS, GHSA-26w7-cxv4-gfx2, plus a low `esbuild` dev-server file read), `sharp@0.35.4` (high, inherited libvips and libheif CVEs), and `@astrojs/starlight@0.42.0` (three moderates across `@astrojs/mdx`, `starlight` and `astro-expressive-code`). Astro 7 and Starlight 0.42 are a coordinated upgrade with its own regression surface, and this site is a *generated view of `skills/`*, so a broken build is a broken product surface. It gets its own PR with its own build verification, not a `--force` inside a security patch.
  - **The exposure, stated rather than implied.** These are build-time dependencies of the docs site: the blast radius is a developer machine and CI, not anyone who installs the plugin. The critical is an XSS in Astro's HTML rendering, and this site is statically generated from repo-controlled markdown and from the registry, with no user input reaching a rendered attribute - so the practical exposure is low. Low is not zero, and "low" is a judgment rather than a measurement, which is why the remaining six stay recorded in `docs/internal/backlog.md` as scheduled work instead of being closed as acceptable.

## [0.14.0] - 2026-09-10

**Runnable recipes: the nine chains this library has advertised since v0.11.0 now run as single commands.** No new skills; the catalog stays 56 core + 7 contested. A recipe used to be a markdown file you executed by hand, running its two to four skills in order and carrying the compressed artifact between them yourself; each now ships a generated command, drift-guarded by a new gate layer. Around that: the library's self-description was made true (all 67 sidecars described a shipped, active skill as an unshipped draft, and the 63 twice-evaluated ones as unmeasured), the CI toolkit pin moved forward while the declared Standard deliberately did not, the three gate layers that guarded everything except themselves gained self-tests, a troubleshooting surface keyed to verbatim error text landed, and five reproduced contested-guard bypasses were closed. The conformance gate goes 14 -> 15 layers and the test suite goes 137 -> 235.

**Standard re-pin review (release-process step 33).** **Both dials held.** The CI pin stays at toolkit `93da438` and `library.json` keeps `"standard": "0.8"`. The toolkit's `main` was **142 commits ahead when this review was run on 2026-09-10** (`git rev-list --count <pin>..origin/main`, merges included; upstream moves, so re-derive it rather than trusting this figure) and three Standard minors ahead (0.13 -> 0.16), and nothing in that gap blocks a feature here - the one thing that did, ADR 0047's workflow-mapped-command resolution, is already in the current pin (that is why the pin moved mid-cycle in #110). The previous posture named Standard 0.15 as the revisit trigger, because the `S3` workflow mirror graduates from `warn` to `error` there and this repo had nine undeclared `_workflows/` recipes. **That trigger is now retired:** #109 declared them, and the pinned run reports zero `S3` findings. The next revisit is whichever comes first - a toolkit fix this repo actually needs that sits past the pin, or the scheduled Standard-debt burn-down. The debt is measured rather than guessed: at the pin declaring `0.8` the repo returns advanced / 0 errors / 129 warnings; declaring `0.13` against that same toolkit returns convergent / 123 errors.

### Added
- **The nine recipes are runnable (#107 phase 1b, #111).** This is the release. A recipe has been a markdown file you read and executed by hand since v0.11.0: run its skills in order (two to four, depending on the recipe), carrying the compressed artifact between them yourself. Each of the nine now ships a generated command, so `/think-stress-test-decision` runs the chain with its documented handoff compression. The commands are **generated, never authored** - `scripts/lib/recipe-command-lib.mjs` is the pure render transform, `scripts/gen-recipe-commands.mjs` the CLI, and a new gate layer (5 of 15) regenerates them and fails on any byte of drift, so a hand-edited command cannot diverge from the chain it claims to run. The recipe body is carried **verbatim**: the numbered handoff lines are the authored value of a recipe, and a generator that emitted a tidy "run these N skills" summary would look correct while destroying the point. Declared under `components.commands`. Footprint measured against the 33,233-char / 67-skill baseline: **+1,802 chars, +5.42%**, roughly 450 tokens per session. Per guardrail 6 that is half the bill - the routing re-run is owed and is not in this release.
- **The changelog gate checks shape, not just version numbers.** `scripts/check-changelog.mjs` gains a `duplicateSections` assertion: no `## [version]` block may repeat a Keep a Changelog change type. That is the defect it was written against - seven PRs each prepended their own block to `[Unreleased]`, leaving `### Added` four times, `### Changed` four times, `### Fixed` three times and `### Security` twice, and the gate stayed green through all seven merges because it only ever compared version numbers. The rule is exported and covered by **9 negative-first tests** (suite 226 to 235), verified red against the live `CHANGELOG.md` before the fix. It is fence-aware, scoped to the six canonical change types (a repeated non-type h3 is a formatting choice, not the prepend defect), and applies to released blocks as well as `[Unreleased]`. `docs/troubleshooting.md` gains the matching verbatim-error entry.
- **A troubleshooting surface, keyed to the actual error text (#105).** `docs/troubleshooting.md` (contributor-facing, every gate-layer failure and its fix) plus a site mirror at `start/troubleshooting` (user-facing: install, invocation, prose-instead-of-artifact, and "the recommendation felt wrong"). Every entry opens with the **verbatim output you would see**, harvested from the scripts rather than paraphrased, so a reader can search for the string in front of them. Linked from the README, `docs/README.md`, contributing, and the site sidebar. This closes the 2026-07-10 audit's only High finding: no user-facing surface covered operational failure.
- **Both quickstarts now show what success looks like (#105).** A truncated real risk register from the premortem worked example, with a pointer to the full artifact. Previously a first-time user had no way to tell a good run from a vague one, which is also what made "I got an essay" hard to self-diagnose. The site version adds the point that makes the artifact usable: every row commits to something observable *before* the failure and to a condition that would make you stop.
- **An after-clone next-step block in `docs/getting-started.md` (#105).** A clone is not an install, and the page previously dead-ended there. A four-row table routes use / read / point-another-agent / contribute.
- **The seven contested-lens samples are reachable (#105).** They all existed and none was linked from the samples index, so browsing for SWOT by name dead-ended. Added with their tiers and the explicit-request framing, plus the reason they are worth reading: a library that only demonstrates its strongest methods is showing a highlight reel.
- **Self-tests for the three guards that guarded everything except themselves (#104, audit findings D-03 and D-06).** `check-counts`, `check-example-coverage` and `check-route-parity` validated the whole repo and had no tests of their own, so nothing proved they could still fail. Their rules are extracted into pure libs (`count-surface-lib`, `example-coverage-lib`, `route-parity-lib`) and covered by **38 negative-first tests** (suite 188 to 226). Each suite leads with the failure the guard exists to catch, and each lib documents the asymmetry that is easy to get backwards: for route parity, a *removed* route fails while an *added* one does not; for example coverage, grandfathering must not mask a different new skill; for counts, a **missing** match is a failure, because rewording prose the pattern was written against is exactly how `docs/README` and `getting-started` drifted to stale counts in the first place.
- **Observability on every generator (audit D-06).** All six `--check` paths now report a tally instead of a bare "OK", so a run that processed zero files stops reading as success: `gen-engine` (bytes compared), `gen-agents` (skill + recipe rows), `gen-catalog` (files verified, named), `gen-recommendable` (corpus size), `gen-registry` (views and entries), `gen-recipe-commands` (commands). `scripts/eval/extract-cases.mjs` also now logs a bullet it cannot use as a case, matching its sibling `extract-output.mjs`; a silently dropped case shrinks the corpus a published accuracy number is computed over. Verified: zero drops on the current corpus.
- **The nine recipes are declared components (#107 phase 1a).** `library.json` gains `components.workflows`, closing a gap that had run since v0.11.0: the README advertised "Recipes | 9 (skill chains shipped as workflow components)" while the manifest declared none of them. The same shortlist also reconciled four candidates honestly - two folds into premortem and two rejects - now published as rejected-with-reasoning Framework Library pages. The honesty bar held throughout: both "M-tier" candidates were downgraded to P before building, and the engine's high fold/reject rate kept breadth from diluting the grade.

### Added
- `think-contradiction-resolution` (tier P, honest read M/P) - a problem-framing skill that reframes a stuck trade-off as a contradiction to dissolve rather than a compromise to optimize: it names the opposing pair, states an implementation-free Ideal Final Result, and runs the four separation principles (time / space / scale / condition), exiting honestly to `think-decision-option-review` when the trade-off is genuinely fundamental. The de-branded core of TRIZ (Altshuller); attributed, not branded (the "TRIZ" trademark was abolished in 2004). Discovered by the SP6 engine discovery run, vetted Build by `think-research-framework`, then built end to end - the platform's first engine-discovered-to-shipped framework. Catalog 34 -> 35 shipped. [SP6]
- `think-boundary-critique` (tier C, honest read C/P) - a problem-framing skill that audits the boundary judgments behind a frame across Critical Systems Heuristics' four sources (who benefits, who decides, whose expertise counts, who has standing) in descriptive "is" and normative "ought" modes, and names the parties affected but excluded. The de-branded core of Ulrich's CSH; attributed, not branded. Discovered by the SP6 engine run and vetted Build. The library's first shipped C-tier framework, graded honestly (a 40-year OR/systems literature but no controlled outcome study, per the Hutcheson/Morton/Blair 2024 review). Catalog 35 -> 36 shipped. [SP6]
- `think-frame-creation` (tier C, honest read C/P) - a problem-framing skill that distils themes and the core paradox from the broader context, abduces a new "approach it as if it were Y" standpoint that redefines what the problem is, and reasons forward to solution directions. The de-branded core of Dorst's Frame Innovation; attributed, not branded. Vetted Build by the SP6 engine (it survives the recipe test against problem-restatement chained with far-analogy-ideation). Graded honestly C (influential design-research theory and case studies, no controlled validation). Catalog 36 -> 37 shipped. [SP6]
- `think-theory-of-constraints` (tier P) - a systems-and-consequences skill that finds the single binding constraint capping a system's throughput and attaches its exploit / subordinate / elevate decisions (Goldratt's five focusing steps), gated on a capacity-versus-demand test so the named bottleneck is the binding step and not the loudest one. Distinct from issue-tree (coverage), iceberg-model (depth), and stocks-and-flows-reasoning (accumulation); its anti-coverage stance (what to ignore) is the value. Graded P, floor and ceiling: a durable, operationally-backed principle whose specific cognitive step has no controlled comparative trial, transferred from human practice. Attributed to Goldratt, not branded. Catalog 37 -> 38 shipped. [v0.5.0 catalog]
- `think-expected-value-decision-tree` (tier P, corrected from a catalog `M` prior) - a decision-and-option-evaluation skill built on the chance node: put explicit probabilities on uncontrolled outcomes, lay out a tree of choice and chance nodes, roll it back to an expected value per option, and add a what-flips-it sensitivity note - with load-bearing false-precision and risk-of-ruin walls. No shipped skill prices uncertainty this way (decision-option-review is deterministic). Honest read S/P capped at P: the S-tier axioms (von Neumann-Morgenstern, Savage) prove EV is the right rule given the inputs, not that drawing a tree makes a real decider better. Generic terms, not branded. Catalog 38 -> 39 shipped. [v0.5.0 catalog]
- `think-scenario-planning` (tier P, corrected from a catalog `M` prior) - a strategy-and-opportunity skill that constructs a set of divergent, internally consistent external futures by crossing the two critical-uncertainty axes (the 2x2), then robustness-tests strategy across the worlds with a signal watch-list - carrying a hard "this is not forecasting" wall. Distinct from futures-wheel (one consequence map), backcasting (one desired path), and premortem (one imagined failure). Downgraded M -> P on the field-expert and review evidence (one supportive student-subject study outweighed by contrary and null findings; the field's own most-cited author calls the evidence "anecdotal"). Adds the 11th cognitive-operation family, **Strategy & Opportunity**. Attributed to Wack / Shell, not branded. Catalog 39 -> 40 shipped. [v0.5.0 catalog]

### Changed
- **v0.5.0 catalog reconciliation (phase 1).** Seven `cand` entries from the v0.5.0 shortlist were re-vetted by `think-research-framework` and resolved against the shipped catalog: `inversion` and `fmea-lite` **folded into `premortem`** (each is premortem's risk-register move; inversion is a frame whose dominant reading premortem already produces, FMEA's one distinct axis - Detection - is an optional column and its weakest-evidenced part); `cognitive-bias-checklist` **rejected on the merits** (`excl`, tier corrected P -> C: the self-scan is the most-undercut debiasing intervention, contradicted by the bias blind spot, and overlaps `ladder-of-inference-check` / `red-team-light` diffusely); `decision-brief-pr-faq` **deferred to pm-skills** (`pm`, tier corrected P -> V: its cognitive core is `pyramid-principle` and its distinctive remainder is a product-management template). The two "M-tier" candidates that became skills were honestly downgraded M -> P before building. Net shortlist outcome: 3 Build, 2 Fold, 2 Reject. [v0.5.0 catalog]
- **Four rejected-with-reasoning dossiers published** to the Framework Library (`inversion`, `fmea-lite`, `cognitive-bias-checklist`, `decision-brief-pr-faq`), each promoted from research staging to `frameworks/<slug>/dossier.md` with the registry-generated status block - bringing the published library to 8 dossiers. The "documented, not shipped" decisions are now browsable, not just recorded. [v0.5.0 catalog]

## [0.4.0] - 2026-06-08

The **Framework Library platform**. The registry (`frameworks/registry.mjs`) becomes the single source of truth for the whole catalog with strong CI; the `think-research-framework` engine produces graded, sourced proposals; the `think-top3` and `think-random-frameworks` applicators put the corpus to work; the published Framework Library renders per-method dossiers; a `/tools/` section separates the meta-skills from the graded frameworks; and the advisor's insufficient-signal gate is calibrated and re-measured. Documentation is refreshed for the registry era.

### Added
- The **framework registry** (`frameworks/registry.mjs`) is now the single source of truth for every evaluated thinking method (102 entries; the 34 `shipped` entries exactly match the skill directories). Migrated from the hand-maintained `framework-catalog.md` (113 table rows reconciled to 102 distinct methods), each entry carries family, evidence tier, status, verdict, reasoning, fold target, and - for branded methods - attribution + trademark. Authored as a zero-dependency ES data module (the repo's scripts are zero-dep and Node ships no YAML parser) with a committed JSON Schema contract, `frameworks/registry.schema.json`. [SP3, #40]
- **Generated, drift-checked views.** `scripts/gen-registry.mjs` regenerates the `framework-catalog.md` family tables (spliced between markers; the hand-authored narrative is preserved) and the public `about/why-not.md` index from the registry, and `--check` byte-compares them - so the catalog and the why-not page can no longer drift from the verdicts. [SP3/SP9, #40]
- **Strong CI around the registry.** `scripts/check-registry.mjs` (a new third layer of the required `check` gate) enforces schema validation, generated-view drift, referential integrity (shipped <-> skill dir both ways with the advisor exempt, recipe -> `_workflows` doc, every fold target resolves to a `shipped` skill, dossier paths and source URLs resolve), completeness (no orphan dossier), the IP/attribution lint (branded requires attribution + trademark), eval-coupling (every shipped entry's `eval/cases.md` exists and is well-formed, reusing the SP1 validator), tier consistency (each shipped entry's governing `tier` is one of the grades in its `SKILL.md` evidence-tier, so the catalog grade cannot drift from the grade the advisor and site publish), and a registry <-> advisor recommendable cross-check. [SP3, #40]
- `.gitattributes` pins LF line endings repo-wide, so the byte-exact drift guards compare identically on Windows (where `core.autocrlf` would otherwise smudge generated files to CRLF) and on Linux CI.
- The **research-framework engine** (`think-research-framework`): a `think-`-prefixed command -> backing meta-skill -> subagent that researches a candidate thinking method, grades it conservatively on the seven-tier model with real sources, assesses overlap against the catalog, drafts a staged dossier (`frameworks/_proposed/<slug>/`), and prints a schema-valid proposed registry entry validated by `scripts/check-proposed-entry.mjs` (with a DRY-extracted `scripts/lib/registry-entry-lib.mjs`). It never writes the registry - a human admits the entry. A `META_SKILLS` exemption lets a meta-skill be a skill dir with no registry entry. [SP5, #41]
- Two **applicator skills** over one shared, drift-guarded engine: `think-top3` (rank the most relevant frameworks, apply the top three, cross-synthesize) and `think-random-frameworks` (draw three at random to break fixation). The shared `references/engine.md` is copied byte-identically by `scripts/gen-engine.mjs` and guarded by a new `gen-engine --check` layer of the conformance gate. Both ship as meta-skills (no registry entry), tier C, experimental. [SP7/SP8, #42]
- The published **Framework Library** on the docs site: `scripts/gen-site.mjs` renders per-method dossiers + a by-family index from the registry, splicing a registry-generated status block between `STATUS:GENERATED` markers in each `frameworks/<slug>/dossier.md` (the committed dossier never carries a status line that drifts); a page renders only when its `dossierPath` resolves, so the library grows without broken links. Shipped with infrastructure + a first dossier tranche (premortem, steelmanning, six-thinking-hats). [SP4, #43]
- A **`/tools/` section** on the docs site for the four meta-skills (advisor, research-framework, top3, random-frameworks): routers and applicators that operate over the library are now presented distinctly from graded frameworks (no evidence-tier badge, no domain link) and dropped from the family tables, lenses, map, chooser, bibliography, and counts. `gen-site.mjs` partitions skills using the registry itself as the discriminator (a skill with no registry entry is a tool). The advisor's prior `/frameworks/think-framework-advisor/` URL is preserved by an Astro redirect, so existing links and bookmarks survive. [decision A, #45]
- Engineer and maintainer documentation: a registry-era rewrite of `docs/architecture.md` (the two sources of truth, the generator pipeline, the four-layer conformance gate, frameworks vs tools, the engine), a repeatable `docs/internal/release-process.md`, a refreshed contributor guide (`docs/contributing.md` + `docs/internal/AUTHORING.md`), and a user-facing tools-vs-frameworks explainer on the site. [#45]
